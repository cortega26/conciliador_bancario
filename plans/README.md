## Findings considered and rejected

- **Buffering `audit.jsonl` writes (one open per event instead of per line).** Not
  worth doing: the per-event open is what makes the append-only guarantee hold, and
  buffering risks losing the audit trail on abnormal termination. Plan 004 makes
  the file run-scoped without changing durability semantics.
- **Enabling `mypy` in CI.** Not part of this set. It reports 18 real errors
  (missing `types-openpyxl` stubs, 5 `__all__` annotations, a genuine
  `no-redef` at `matching/engine.py:282`, and 3 incompatible-exception
  assignments at `cli/app.py:91-95`). Wiring it in as-is turns CI red immediately
  and is a separate piece of work. The config exists and is pinned; the gap is
  recorded, not silently closed.
- **Unifying `_id_tx` hash keys across the four ingestion adapters** (CSV uses
  `{"file","row","data"}`, the others `{"file","idx","data"}`, so the same
  statement gets different `TX-` ids depending on format). Real, but it changes
  every derived id, invalidates all six golden fixtures, and needs a
  `MODELO_INTERNO_VERSION` bump. It is a cross-format contract change, not a bug
  fix — do it deliberately, not as a side effect of these plans.
- **Collapsing the duplicated CSV/XLSX adapters (~330 lines, already diverged).**
  Real debt, wrong moment. Plans 002/003/006 touch those files; do the
  consolidation first or not at all in this batch.
- **`prevenir_csv_injection` whitespace bypass.** Genuine, but plan 006 hardens the
  same function, so it rides along there.
- **`mask_por_defecto` / `rut_mask` being unread config keys.** Real, and reported
  to the maintainer as its own item. It changes `run_id` (the fingerprint at
  `pipeline.py:248` includes `mask`), which would invalidate all six golden
  fixtures — that coupling is out of scope for this batch.
